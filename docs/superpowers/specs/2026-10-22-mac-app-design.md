# CarBUS.app — программа для Mac без Docker и Терминала

Дата: 22.10.2026. Статус: решения согласованы с Игорем в разговоре; «остальное делай».

## Зачем

CarBUS for Mac сейчас запускается так: Docker Desktop, `git clone`, `docker compose up`, мост
`./run-bridge.sh` в Терминале. Это годится разработчику. Программой будет пользоваться человек,
у которого на маке ничего не установлено и который не знает, что такое Docker: он хочет «скачал —
запустил». Нужен обычный значок CarBUS в «Программах», который открывает своё окно и сам
находит прибор.

## Что получает пользователь

1. Ссылку на страницу загрузки (GitHub Releases) и инструкцию с картинками.
2. Скачивает `CarBUS-<версия>.dmg`, перетаскивает CarBUS в «Программы».
3. Первый запуск: macOS говорит «Файл «CarBUS» не был открыт» → «Готово» → «Системные
   настройки» → «Конфиденциальность и безопасность» → «Всё равно открыть» → «Открыть файл
   «CarBUS»?» → «Всё равно открыть» → Touch ID или пароль. Один раз на каждую скачанную версию.
4. Дальше — двойной щелчок по значку: окно CarBUS с тем же интерфейсом, что сейчас в Chrome.
   Прибор по USB программа находит сама. ⌘Q или закрытие окна — программа завершается целиком.
5. Новая версия — скачать свежий .dmg по той же ссылке и заменить программу (снова шаг 3).

## Решения Игоря

- Установщик — `.dmg` без подписи разработчика (учётной записи Apple Developer нет);
  неподписанную программу пользователь разрешает через «Всё равно открыть». Команда в Терминале
  для пользователя сложнее, её не используем.
- Своё окно, а не вкладка браузера.
- Обновления пользователь скачивает сам; программа о новых версиях не сообщает.
- Docker-образ и мост остаются — для разработки и Linux.

## Как устроено (решения исполнителя)

- **Окно** — небольшая программа на Swift (AppKit + WKWebView, движок Safari): меню («О
  программе», «Показать трейсы в Finder», «Правка» — без неё не работают ⌘C/⌘V, «Окно»),
  загрузка файлов (`<input type=file>`), скачивания (RX-List, «Скачать»), alert/confirm, внешние
  ссылки — в браузер по умолчанию. Размер и положение окна запоминаются.
- **Бэкенд внутри программы** — автономный Python 3.12 (python-build-standalone, версия и
  контрольные суммы закреплены) с зависимостями бэкенда, код `backend/app` и собранный
  `frontend/dist` лежат в `Contents/Resources`. Окно запускает `python -m app.desktop`, ждёт
  ответа сервера и показывает интерфейс; при выходе останавливает бэкенд.
- **`app.desktop`** — точка входа «программы для мака»: сервер на `127.0.0.1:<порт>`, мост
  выключен, бэкенд завершается сам, если окно пропало (процесс-родитель сменился: окно убито,
  упало). Порт постоянный — 47800, чтобы раскладка окна в хранилище WebKit (оно привязано к
  адресу) переживала перезапуск; занят — окно берёт свободный порт (раскладка тогда по
  умолчанию).
- **Режим без моста.** Сейчас поиск приборов всегда опрашивает мост, и без него окно пишет «Мост
  не запущен (host.docker.internal:7700)» и про Docker. В программе мост выключен: состояние моста
  «off», «Дополнительно» с адресом моста не показывается, подсказка без прибора — «Подключите
  CAN-Hacker к USB». Docker-вариант не меняется.
- **Где данные.** `~/Library/Application Support/CarBUS/data` и `…/traces`, журналы —
  `~/Library/Logs/CarBUS/`. Не «Документы»: подпись ad-hoc меняется с каждой сборкой, и macOS
  после каждого обновления заново спрашивала бы доступ к защищённой папке.
- **Пакет пишет только вне себя.** `.pyc` собраны заранее, Python запускается с
  `PYTHONDONTWRITEBYTECODE=1`: запись внутрь .app ломает подпись, а из .dmg/при App
  Translocation пакет вообще только для чтения.
- **Одна программа для всех маков.** Окно — универсальный Mach-O (arm64 + x86_64). Python и
  бинарные зависимости собираются для обеих архитектур и сшиваются `lipo` в универсальные файлы.
  Пользователю не нужно знать, какой у него процессор.
- **Подпись** — только ad-hoc (`codesign -s -`): каждый вложенный Mach-O, затем пакет. На Apple
  Silicon без подписи код не запускается вовсе.
- **Сборка** — `macos/build-app.sh` (локально и в CI) собирает `CarBUS.app` и `.dmg` (CarBUS +
  ярлык «Программы»). GitHub Actions на тег `v*` собирает .dmg, проверяет обе архитектуры
  (x86_64 — через Rosetta на раннере) и выкладывает в Releases.
- **Значок** — свой, нейтральный (без знаков canhacker.ru), генерируется скриптом.

## Не делаем

Подпись Developer ID и нотаризацию, автообновление, App Store, песочницу (sandbox), сборки для
Linux/Windows, отдельную службу.

## Чего нельзя допустить

- Пользователю нужен Терминал, Docker или мост.
- В окне программы упоминаются Docker, мост, `./run-bridge.sh`.
- Программа пишет в свой пакет или в защищённые папки (запросы доступа после обновлений).
- После закрытия окна остаётся работающий бэкенд.
- Тесты передают в шину без явного «да» Игоря; на машине — только «Только слушать».

## Проверено макетом (22.10, macOS 27.0.1, Apple Silicon)

Окно WKWebView + встроенный python-build-standalone 3.12.15 + бэкенд: интерфейс и WebSocket
работают при `NSAllowsLocalNetworking`; прибор найден по USB без моста; карантинный .dmg
открывается после «Всё равно открыть» (снимки — `docs/screenshots/install/`), вложенный Python под
карантином запускается. Пакет 105 МБ, .dmg 80 МБ.

## Оставлено исполнителю

Вид значка, текст страниц ошибок окна, состав «ужатого» Python (что выкинуть: tkinter, тесты,
pip), раскладка .dmg.
