# CarBUS for Mac — паритет интерфейса с десктопом (этап 1: CAN-ядро)

Дата: 2026-10-20. Статус: решения исполнителя по прямому указанию пользователя
(«Делай сразу»; вопросы по устройству десктопа — «сам можешь глянуть»).
Предыдущий спек v1: `2026-10-20-carbus-mac-port-design.md` (архитектура
мост → Docker → браузер остаётся без изменений).

## 1. Зачем

Поэлементная сверка (DFM-формы + браузер, 2026-10-20) показала, что UI v1 — упрощённая
панель, а не интерфейс десктопа: нет контекстных меню, хоткеев, Clear, раздельного
приёма, агрегатора, редактора отладчика, ручного битрейта, а комментарий и триггеры
сделаны иначе. Пользователь хочет **полноценный интерфейс десктопной CarBUS Analyzer**,
удобный на экранах **от 1366×768**, с проверкой юзабилити по ходу работы.

## 2. Источники истины

- Формы десктопа: `docs/reference/carbus-dfm/*.dfm.txt`, сводка `UI_MAP.md`.
- Руководство пользователя (70 стр., со скриншотами):
  `~/dev/canH/CarBUSAnalyzer-0.10.37.911-r4331-full/app/Руководство пользователя.pdf`.

  кодом (формат `.trc`, см. §8).

## 3. Цели этапа 1

Повторить рабочие окна десктопа для классического CAN (2 канала прибора HW_CH32):

1. **Главное окно**: строка меню (Файл · Подключиться · Поток · Отладчик · Настройки · ?),
   тулбар с иконками и подсказками (текст + хоткей), область приёма, док передачи снизу,
   панель фильтров справа, статусбар (состояние, прибор, каналы, запись, скорость приёма).
2. **Монитор** (`frameReceive`): колонки `CH · Флаги · ID · DLC · Данные · Период ·
   Счётчик · FC · ASCII · Комментарий`; подсветка изменившихся байт цветом на заданное
   время («Сбросить после», 500–10000 мс, по умолчанию 2000); режим редких данных
   (период 100–10000 мс, по умолчанию 10000); контекстное меню (Сохранить RX-List,
   Загрузить поток, Очистить, Битовая карта, Комментарий, Копировать в TX-List Ctrl+↓,
   Добавить ID в фильтр, ID в HEX, Сортировать, Группировать по каналам); раздельный
   приём по каналам.
3. **Битовая карта** (`frmDetails`): плавающее окно на сообщение (можно несколько):
   x80…x01 + «Dec byte», подсветка изменившихся бит, комментарий.
4. **Агрегатор уникальных данных** (`dlgFramesView`): колонка FC + окно «[CH] ID: Данные
   сообщения» со списком уникальных payload (период, счётчик, ASCII, комментарий).
5. **Поток** (режим Поток, F2): колонки `Время · Флаги · CH · Rx/Tx · ID · DLC · Данные ·
   ASCII · Комментарий`; Rx и Tx; запись/пауза (F5), очистка, метки (F8 с диалогом,
   F9 авто), список меток с переходом, загрузка/сохранение трейса, «Открыть в отладчике»
   (Ctrl+F12); в статусбаре «Запись», число кадров, длительность.
6. **Передача** (`frameCANTasks`): таблица задач (флажок цикла, CH, Флаги, ID, DLC,
   Данные, Период, Счётчик, Комментарий); редактор: Канал, ID, DLC, 8 полей-байт,
   Комментарий, 29 bit, RTR, Период (1–10000, по умолчанию 10), Значение + Заполнить;
   кнопки Послать · Добавить · Старт/Пауза · Копировать · Удалить; **триггер задачи**:
   Действие (Нет/Одиночный/Старт/Стоп), Задержка (0–10000 мс), Триггер Ch (Все/1/2), ID,
   DLC, 8 полей данных (пустое поле = любое значение); контекстное меню (Добавить,
   Копировать, Удалить, Очистить список, Одиночный, Старт/Пауза, Запустить все,
   Остановить все, Сбросить счётчик, Сбросить все счётчики, Загрузить, Сохранить);
   Enter = Послать.
7. **Фильтры** (правая панель, Ctrl+F): вкладка «Фильтр ID/Маска» — таблица аппаратных
   слотов (флажок, CH, Num, ID, Маска) по `filters_info` прибора, диалог «Установить
   фильтр по маске» (ID, Маска, 29 bit, Включить), загрузка/сохранение; вкладка «Фильтр
   Диапазон» — дерево программных диапазонов по каналам с исключениями (ID/Маска),
   флажки включения, диалоги диапазона и исключения; «Простой режим» (маска скрыта =
   0x7FF/0x1FFFFFFF). Программные фильтры отсеивают кадры **до** монитора, потока и записи.
8. **Подключение и каналы**: диалог «Настройки устройства» — мост (хост:порт) и вкладки
   «Канал 1/2: CAN»: название, номинальная скорость (пресеты carbus-lib + свои),
   «…» → «Управление скоростями» (тактовая 120 МГц из прибора, скорость, точка выборки
   50–90 %, по умолчанию 75 %, Prescaler/Seg1/Seg2/SJW, фактическая скорость и SP,
   точность, Добавить/Удалить/вверх/вниз), «Только слушать», «Включить терминатор
   120 Ом», «Открывать после подключения». «Принять» = (пере)подключение. Меню опций
   канала на тулбаре: информация об устройстве, терминатор (вкл/выкл на лету).
9. **Отладчик** (F12, отдельный вид): меню Трейс/Комментарий; тулбар (Открыть,
   Комментарий, Таблица ID Ctrl+F3, Пауза между сообщениями, ▶/❚❚ F9, Шаг F8, В цикле,
   Передавать выделенные, Точка назначения: Канал 1/Канал 2/Окно Приём, Копировать в
   TX-List, Точка останова F5, Список точек Ctrl+F5); «Остановить при получении данных»,
   «Остановить в точке останова», «Только для канала»; таблица кадров с выделением
   (Shift — диапазон, Cmd/Ctrl — отдельные), правка (Добавить Ins, Вставить Ctrl+Ins,
   Редактировать Ctrl+Enter, Удалить Ctrl+Del, Копировать Ctrl+C, Запретить/Разрешить
   строку/выделенные/по ID, Начало/Конец трейса); окно редактора кадра (ID, 29 bit, DLC,
   данные, RTR, задержка до/после, Значение + Заполнить); таблица ID справа (флажки,
   Сбросить всё/Выбрать всё/Инвертировать/Найти/Выделить/Снять/Запретить/Разрешить);
   задержки: по меткам времени, 10–50 мс, своя 10–9999 мс (по умолчанию 100), «Макс.
   1 сек»; статус: прогресс, «Текущая строка», «Строк: N из M», «Передача в канал …»,
   «Пауза: …».
10. **Настройки приложения**: стиль (светлая/тёмная/как в ОС), шрифт таблиц (семейство,
    размер 11–18), приём (подсветка, цвет, «Сбросить после», агрегатор), передача
    (восстанавливать список при запуске), поток и трейсер («Макс. 1 сек», формат
    копирования строк: заголовок, ID HEX/DEC, Data HEX/DEC), фильтр (новый фильтр активен,
    восстанавливать при запуске, простой режим), фоновое логирование потока (старт при
    подключении, писать TX, маска имени файла, мета: тип транспорта/марка/модель/кузов/год).
11. **Хоткеи** (как в десктопе): F2, F3, Ctrl+F3, F4, F5, F8, F9, F12, Ctrl+F12, Ctrl+N,
    Ctrl+F, Ctrl+↓; в отладчике — свой набор (§ п.9). На маке остаются Ctrl-сочетания
    десктопа (Cmd-сочетания браузер перехватывает).
12. Интерфейс **на русском** (строки из `Russian.lng`), все строки в одном модуле.

## 4. Не-цели этапа 1 (следующие этапы, отдельными планами)

DBC (менеджер, сигналы в комментариях, графики), LIN (carbus-lib не умеет кадры LIN),
CAN Bomber / LIN Bomber, шлюз CAN1⇔CAN2, загрузка устройства (статистика), ALS,
автоопределение скорости, JS-консоль, импорт форматов 7GIS / CAN Spy / Vega, CAN-FD,
язык интерфейса кроме русского. Отдельные браузерные окна не делаем — «окна» десктопа
становятся плавающими панелями и видами внутри одной страницы.

## 5. Ограничения

- Целевой экран ≥ **1366×768**; проверяем вьюпорты **1366×768** (Chrome во весь экран)
  и **1366×650** (окно Chrome на экране 768), плюс 1920×1080. Ничего не обрезается, нет
  горизонтальной прокрутки страницы, текст ≥ 12 px, контраст текста ≥ 4.5:1.
- Chrome. Docker на маке, нативный мост — как в v1. Ни одного внешнего сервера.
- Протокол прибора — только через carbus-lib 0.1.9. Закрытия канала в протоколе нет
  (только `DEVICE_CLOSE`), поэтому смена скорости = переподключение (как в десктопе:
  «Принять» в диалоге устройства).
- Временные метки прибора — 32-битные мкс (переполнение каждые ~71,6 мин) → бэкенд
  разворачивает их в монотонное время.

## 6. Решения исполнителя (мои калы)

- **Фронт**: Preact + @preact/signals (JSX через esbuild Vite), `lucide-preact` для
  иконок. Высокочастотные таблицы — собственный виртуальный грид (фиксированная высота
  строки, рендер только видимых строк, обновление ячеек на месте, без VDOM на каждом тике).
- **Единый реестр действий** (как `TActionList`): id, подпись, хоткей, иконка,
  enabled/checked, run — из него строятся меню, тулбар, контекстные меню и хоткеи.
- **Бэкенд — одно состояние на процесс (`Hub`)**, а не на WebSocket: перезагрузка
  страницы не рвёт подключение, запись и передачу; новый клиент получает снапшот `hello`.
- **Протокол WS**: команды `{type, req_id?, …}`, ответы `{type:"reply", req_id, ok, data|error}`,
  события сервера — по типам (§7). Тик сервера 40 мс (25 Гц) как в v1.
- **Буфер потока — на бэкенде**, колоночный (массивы `array`), до 5 000 000 кадров;
  фронт читает видимые диапазоны (`capture_rows`) и получает «хвост» в тиках.
- **Хранилище состояния**: JSON-файлы в `./data` (монтируется в контейнер, как
  `./traces`): settings, connection, transmit, filters, comments, bitrates, recent.
- **Комментарии сообщений** — по ключу `ID + 11/29 бит` (без канала).
- **Сохранение трейса**: по умолчанию `.trc` (совместим с десктопом, §8); вариант
  `.jsonl` (наш, сохраняет Rx/Tx и источник метки). Файлы — в `./traces`; в диалоге
  файлов есть загрузка с компьютера и скачивание.
- **Время в таблицах**: секунды с запятой и 3 знаками («12,453»), как в RU-десктопе;
  относительно первого кадра потока/трейса.
- **Раскладка** (1366×650): меню 28 px, тулбар 38 px, статусбар 24 px; область приёма
  сверху, док передачи снизу (по умолчанию 270 px, сворачивается и тянется), панель
  фильтров справа (340 px, скрываемая). Отладчик — отдельный вид на всю рабочую область
  (переключение F12 / пункт меню), приём продолжает работать в фоне.
- **Тема**: светлая и тёмная через CSS-токены, по умолчанию «как в ОС».
- Демо-источник кадров для разработки и проверки UI: `python -m app.demo` (без прибора).

## 7. Состав событий сервера (контракт для плана)

`hello` (полный снапшот), `status` (подключение, device_info, каналы), `monitor_delta`,
`monitor_reset`, `capture_state`, `capture_tail`, `tx_state`, `tx_counts`,
`filters_state`, `settings`, `comments`, `tracer_state`, `tracer_progress`, `toast`,
`error`. Точные поля — в плане.

## 8. Формат `.trc` десктопа (восстановлен из бинарника, REA/Ghidra)

Наблюдения (evidence: `FUN_009b0290` пишет заголовок, `FUN_009b0160` + `FUN_0099b5b0`
пишут строки, `FUN_009af270` / `FUN_009aeed0` / `FUN_009af810` / `FUN_0099a0e0` читают):

- Строка 1: `@ TEXT @ 3 @ 64 @ 0 @ <кол-во строк> @ <длительность мс> @ [<N>d ]hh:nn:ss.mmm @`
  (при чтении двойные пробелы схлопываются, `split('@')` даёт 9 частей, часть 1 = `TEXT`,
  часть 2 = версия 1…3).
- Далее строки `# key=value`, в т.ч. `# $LocalTime=HH:MM:SS.mmm`.
- Метка: `------\t<метка>\t<комментарий>`.
- Кадр (версия 3), 9 полей через TAB:
  `СС,мкссс\tCH\tФЛАГИ(%08x)\tID(hex)\tDLC\tДанные("XX XX …")\t%08x\tASCII\tКомментарий`.
  Время = секунды **по модулю 60** и микросекунды через запятую; при чтении переход
  через минуту разворачивается (+60 с). Флаги: бит 0 = 29-битный ID, 0x4 = классический
  CAN, 0x10 = CAN-FD, 0x100 = LIN; RTR — бит 1 (вывод). Строки заканчиваются CRLF.
- **Неизвестно**: бит направления Rx/Tx и смысл 7-го поля; версии 1–2 построчно не
  восстановлены. Решение: читаем v3 (LIN-кадры пропускаем с подсчётом), версии 1–2 —
  явная ошибка «неподдерживаемая версия»; пишем v3 с флагами `0x4|ext|rtr`, 7-е поле
  `00000000`, направление в `.trc` не кодируем (для него есть `.jsonl`).

## 9. Проверка

- Бэкенд: pytest на каждый модуль (монитор, буфер потока, форматы трейсов, передача и
  триггеры, фильтры, отладчик, хаб через WS TestClient).
- Фронт: vitest на чистые модули + компонентные тесты (@testing-library/preact, happy-dom)
  для действий/хоткеев/диалогов.
- **Юзабилити — после каждой UI-задачи**: `python -m app.demo` → Playwright на
  1366×768 и 1366×650 → скриншот, просмотр глазами, плюс скрипт-аудит раскладки
  (переполнение страницы, обрезанные элементы, мелкий шрифт).
- В конце — ручная проверка на приборе пользователем (шина), пункты в README.
