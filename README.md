# CarBUS for Mac

Порт десктопной CarBUS Analyzer (Windows) для программатора **CAN-Hacker v3.2**
(HW_CH32) на macOS: монитор шины, битовые карты, поток с записью трейсов, передача
с триггерами, фильтры, отладчик трейсов, фоновое логирование. Бэкенд — Python/FastAPI
и [`carbus-lib`](https://pypi.org/project/carbus-lib/) в Docker, интерфейс — в Chrome.

Окна, подписи и хоткеи повторяют русскую версию десктопа (формы восстановлены из
бинарника, см. `docs/reference/carbus-dfm/`). Что сделано, а что нет — по каждой форме
в `docs/reference/carbus-dfm/UI_MAP.md`, раздел «Статус порта».

## Почему нужен мост на маке

Docker Desktop на macOS запускает контейнеры в Linux-VM и **не прокидывает USB**.
Поэтому USB-порт программатора держит тонкий нативный мост на самом маке
(`run-bridge.sh`, штатный `carbus_async.tcp_bridge`), а контейнер подключается к нему
по TCP через `host.docker.internal`.

## Запуск

1. Подключите программатор по USB и запустите мост:

   ```bash
   ./run-bridge.sh          # найдёт /dev/cu.usbmodem* и отдаст его на :7000
   ```

2. В другом терминале поднимите контейнер:

   ```bash
   docker compose up --build
   ```

3. Откройте в **Chrome** <http://localhost:8000> и нажмите **«Подключиться»** — откроется
   «Настройки устройства»: мост (по умолчанию `host.docker.internal:7000`), для каждого
   канала — название, номинальная скорость (стандартные или свои из «Управление
   скоростями» по кнопке «…»), «Только слушать», терминатор, «Открывать после
   подключения». «Принять» подключает; при открытом соединении — переподключает
   (закрыть отдельный канал протокол прибора не умеет, скорость меняется только так).

Интерфейс рассчитан на экран от **1366×768**.

## Где лежат данные

| Папка на маке | Что внутри |
|---|---|
| `./traces` | трейсы: «Сохранить поток», файлы фоновой записи; отсюда их открывают «Загрузить поток» и отладчик. Форматы: `.trc` (как у десктопа, v3) и `.jsonl` (наш, сохраняет Rx/Tx) |
| `./data` | настройки, подключение, свои скорости, список передачи, фильтры, комментарии; `data/lists/` — файлы списков: комментарии `.cmt`, задачи передачи `.tsk` (форматы десктопа) и наш `.json` |

В диалогах файлов есть «Загрузить с компьютера…» и «Скачать». Состояние живёт на
сервере: перезагрузка страницы не рвёт подключение, запись и передачу.

## Что есть на этапе 1

- **Монитор**: CH, Флаги, ID, DLC, Данные, Период, Счётчик, FC, ASCII, Комментарий;
  «послесвечение» изменившихся байтов на время «Сбросить после»; редкие данные;
  контекстное меню; раздельный приём по каналам; комментарии ID (`.cmt` десктопа).
- **Битовая карта** (F3) и **«Данные сообщения»** (Ctrl+F3) — плавающие окна.
- **Поток** (F2): Rx и Tx с временем, запись F5, метки F8/F9, список меток, сохранение и
  загрузка трейса, «Открыть в отладчике» (Ctrl+F12).
- **Передача**: задачи с периодом, флажок цикла, одиночная отправка, триггеры
  (Нет/Одиночный/Старт/Стоп, задержка, канал, ID, DLC, данные с «любым» байтом),
  списки `.tsk`.
- **Фильтры** (Ctrl+F): аппаратные слоты прибора (ID/Маска) и программные диапазоны с
  исключениями, «Простой режим».
- **Устройство**: подключение, «Управление скоростями» (подбор Prescaler/Seg1/Seg2/SJW по
  скорости и точке выборки, фактическая скорость и точность), «Информация об
  устройстве», терминатор на лету в меню опций каналов.
- **Отладчик** (F12): трейс с таблицей используемых ID (неотмеченные скрываются и не
  воспроизводятся), воспроизведение в канал 1/2 или в окно приёма, пауза по меткам
  времени или фиксированная, цикл, выделенные строки, точки останова, начало/конец,
  правка строк, копирование строк в TSV.
- **Настройки приложения**: тема (светлая/тёмная/как в ОС), шрифт таблиц 11–18,
  подсветка, восстановление списков, формат копирования, фильтры.
- **Фоновое логирование**: пока прибор подключён, кадры пишутся в `.trc` по маске имени
  с метаинформацией (тип транспорта, марка, модель, кузов, год).

## Хоткеи

| Окно приёма | | Отладчик | |
|---|---|---|---|
| F2 | Монитор / Поток | F9 | Запуск / пауза |
| F3 / Ctrl+F3 | Битовая карта / Данные сообщения | F8 | Шаг |
| F4 | Комментарий к сообщению | F5 / Ctrl+F5 / Shift+F5 | Точка останова / список / удалить все |
| F5 | Запись потока | Ctrl+F3 | Таблица используемых ID |
| F8 / F9 | Метка / автоматическая метка | F4 | Комментарий |
| Ctrl+N | Сбросить полученные данные | Ctrl+N / Ctrl+O | Новый / открыть трейс |
| Ctrl+F | Панель фильтров | Ctrl+S / Ctrl+Shift+S | Сохранить / сохранить как |
| Ctrl+↓ | Копировать в TX-List | Ins / Ctrl+Ins | Добавить / вставить строку |
| Ctrl+F12 | Открыть поток в отладчике | Ctrl+Enter / Ctrl+Del | Редактировать / удалить строку |
| F12 | Отладчик | Ctrl+C | Копировать выделенные строки |

Сочетания с **Ctrl**, как в десктопе: Cmd-сочетания остаются браузеру. На клавиатуре
мака нет Insert, а Del — это fn+Delete; все действия с этими клавишами есть в
контекстном меню таблицы трейса.

## Чего нет на этапе 1

DBC (менеджер, сигналы, графики), LIN, CAN-FD, CAN/LIN Bomber, шлюз CAN1⇔CAN2,
загрузка устройства (статистика), ALS, автоопределение скорости, JS-консоль, импорт
форматов 7GIS / CAN Spy / Vega, языки кроме русского. «Отдельные окна» десктопа стали
панелями и видами внутри одной страницы. В «Настройках фонового логирования» одна
конфигурация (без списка пресетов десктопа).

## Проверка на реальной шине (вручную)

Автотесты гоняют бэкенд на заглушке прибора и демо-источнике. На железе перед
работой стоит пройти:

1. Мост запущен, «Подключиться» → «Принять» с **«Только слушать»** — в статусе прибор,
   прошивка, серийный номер и скорости каналов; в мониторе идут кадры с шины.
2. «Информация об устройстве»: каналы, частота, число фильтров; терминатор включается
   только если прибор его поддерживает.
3. F5 → несколько секунд записи → «Сохранить поток» в `.trc` → «Загрузить поток» и
   открытие в отладчике; при желании — открыть файл в десктопной CarBUS Analyzer.
4. Только на стенде (не на машине в движении): снять «Только слушать», одиночная
   отправка из «CAN Передача», затем задача в цикле и триггер.
5. Фильтры: аппаратный слот по ID и программный диапазон — лишние кадры пропадают из
   монитора.
6. Отладчик: воспроизведение в «Окно Приём», затем на стенде — в канал.

## Безопасность

- Интерфейс и WebSocket слушают только `127.0.0.1` мака.
- Мост по умолчанию тоже слушает только `127.0.0.1`: Docker Desktop достаёт сервисы
  хоста на loopback через `host.docker.internal`, в локальную сеть мост не
  публикуется. Если ваш рантайм не дотягивается до loopback — запустите
  `CARBUS_BRIDGE_HOST=0.0.0.0 ./run-bridge.sh` и держите firewall включённым.
- Публичный relay из `carbus-lib` **не используется** — трафик шины наружу не уходит.

## Разработка

```bash
# бэкенд
cd backend && python3 -m venv .venv && .venv/bin/pip install -e ".[dev]"
.venv/bin/pytest -q
.venv/bin/python -m app.demo --port 8765    # демо без прибора: http://127.0.0.1:8765
# на реальном железе: запустить мост, затем
CARBUS_BRIDGE=127.0.0.1:7000 .venv/bin/pytest -q tests/test_carbus_session_smoke.py

# фронт
cd frontend && npm install
npx vitest run && npx tsc --noEmit -p .
npm run build       # статика для бэкенда (frontend/dist)
npm run dev         # vite dev-сервер
```
